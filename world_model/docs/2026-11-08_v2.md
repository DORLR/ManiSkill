# 2026-11-08: v2 (angle loss, no KL, tracking history, predicted-pose loss) and why it was stopped

Code: archived with v1 (`$Q/archive/world_model_code_v1_v2_2026-11-08.tar.gz`). Configs:
`configs/archive/v2/`. Results: `docs/results/vae_v2_val_log.jsonl`, `wm_v2_val_log.jsonl`, `v2_*.json`.

## Changes from v1 (all trained from scratch)

* VAE: `+ 2.0 x angle error` (angle between predicted and true remaining rotation, same FK label as
  the plug-point loss), KL removed (deterministic encoder). 60k steps, `runs/vae_v2`, best step 56k.
* CDiT: condition = next 8 joint targets + 24 steps of "commanded target - measured joints" (224);
  `+ 0.02 x predicted-pose loss` (pose head on the model's clean-latent estimate vs on the true next
  latent, diffusion steps t < 200). Still one-step only. `runs/wm_v2`, stopped at 154.4k by the user.
* A first attempt fine-tuned both from v1 checkpoints. It was stopped and deleted (user): a fine-tuned
  model keeps the old latent space, so it cannot show whether the new design works; and a WM on old
  latents is useless once the VAE changes. Rule since: a changed design is retrained from scratch.

## Results

VAE v2: plug-point 0.69-0.74 mm (v1 0.64, slightly worse), angle error 0.41-0.45 deg.
Offset R^2 from the latent (MLP) / pose head (linear):

| | lateral y | lateral z | roll | pitch | yaw |
|---|---|---|---|---|---|
| v1 latent | 0.80 | 0.67 | 0.43 | 0.74 | 0.61 |
| v2 latent | 0.76 | 0.57 | 0.72 | 0.73 | 0.88 |
| v1 pose head | 0.70 | 0.58 | 0.36 | 0.02 | 0.19 |
| v2 pose head | 0.69 | 0.49 | 0.82 | -0.07 | 0.88 |

Roll and yaw fixed; pitch still unreadable by the pose head (cause not established: label noise from
clearance in the hole, or a frame mismatch between the truth offset and the fitted port axes -- to be
checked). Jam AUC from the latent unchanged (0.863 vs 0.869).

CDiT v2 (one step, best 150k): translation 0.40-0.41 mm (copy 0.69), rotation 0.13 deg (copy 0.14-0.16:
better than copy for the first time), joints 3.2 mrad (copy 2.7: still worse). Plateau after ~75k.

Stall check, jammed trials, windows after the first 0.4 s of the push:

| | progress per 0.4 s | windows with < 0.2 mm |
|---|---|---|
| real | 0.38 mm | 41% |
| v1 | 0.85 mm | 28% |
| v2 | 0.76 mm | 35% |

In the first 0.4 s of a push the plug has not reached the hole yet (both outcomes progress ~0.93 mm),
so that window cannot test foresight; only multi-step prediction can.

Multi-step (imagined) rollouts: invalid for v1 and v2. The action condition needs the current joints;
in imagination they had to be decoded from the predicted latent (one joint token). Its error (3.2 mrad
per step, > the 2.7 mrad the arm moves per step) feeds back: the action input grows 0.016 -> 0.031 ->
0.089 -> 3.67 -> NaN within 4 steps. The `v*_wm_contact_rollout.json` files contain these broken runs.

## Why v2 was stopped and what v3 changes (decided with the user)

1. The WM only predicted one step (rel_t fixed to 0.4 s) although CDiT has NWM's time-shift input.
2. Joints were represented inside the latent and decoded in imagination; Ctrl-World never lets the
   world model predict joints (an adapter maps current joints + action to future joints, FK gives the
   hand poses that condition the WM).
3. The WM could not tell "commanded to stay" from "blocked": it saw no commanded vs measured hand poses.
4. The VAE dropped pixels without depth (most of the plug: only 28% of plug pixels have depth) and used
   a hand-written plug/port split. The user asked for RGB-D as the camera gives it.
